## What was built

Self-contained road routing on `roads.gpkg` (HotOSM Tunisia), no paid APIs and
no live network calls at query time.

**New files**

- `src/backend/tool/gpkg_roads.py` — pure-stdlib GeoPackage/WKB reader.
  GDAL and shapely are not installed on this host, so it decodes the GPKG binary
  header plus WKB by hand.
- `src/backend/tool/build_road_graph.py` — builds `data/road_graph.npz`
  (not shipped; 152 MB, regenerated by running this script against
  `C:\Users\cy1in\Downloads\roads\roads.gpkg`).
- `src/backend/app/road_routing.py` — CSR graph + grid snap index + A*,
  per-mode (car/foot/bike), returning real polylines and road names.
- `src/backend/tool/verify_road_routing.py` — 30 assertions on the graph.
- `src/backend/tool/verify_integration_roads.py` — end-to-end through the router.

**Modified**

- `src/backend/app/routing.py` — legs whose endpoints are not two stations
  joined by a transit line now use the road graph: access walk, final walk,
  walking transfers, and taxi/louaj legs. `resolve_walk_geometry()` does this
  lazily per leg.

## Bugs found and fixed during the build

These are the parts most worth reviewing, because each produced silently wrong
output rather than an exception.

1. **`uint8 & bit` is not a numpy mask.** `eflags` is `uint8`, so
   `flag_a & bit` stays `uint8` and `eu[mask]` becomes *integer fancy indexing*,
   not a boolean mask. It silently selected one index repeatedly, collapsing
   12.6M car edges to 2 distinct sources and producing nonsense component
   counts. Needs `.astype(bool)`.

2. **A* on an unreachable pair exhausts its whole component** — measured 10-22 s
   each, and four of them made one Tunis→Carthage request take 43 s. Fixed with
   `UNREACHABLE_COST_FACTOR = 25.0` (cap search cost at 25x straight-line travel
   time) plus per-mode connected-component labels so mismatched pairs skip in
   O(1). Request time went 43.3 s → 1.8 s with byte-identical distances.

3. **Component labels are necessary but NOT sufficient for reachability.** They
   are computed on the undirected view, but a one-way street has a forward edge
   and no reverse twin, so 56,351 of 12.6M car edges are cross-component. The
   label check is only ever used to skip a search, never to accept one.

4. **Snapping to only the nearest node loses real paths.** A station 125 m from
   its destination snapped in foot mode onto a degree-1 dead-end stub of an
   unnamed way; A* found the pair disconnected while the *second* nearest node,
   30 m further, was on a through street. Hence `_snap_candidates()` + a bounded
   nearest-first retry (`SNAP_CANDIDATES = 6`, `FALLBACK_ASTAR_TRIES = 4`).

## Known open problems — please address these

1. **One 125 m walk in central Tunis still falls back to a two-point line**
   (36.8003841,10.1903877 → 36.8006935,10.1917429). Both endpoints land in
   genuinely disconnected foot components (37141 vs 37134) and no nearby foot
   node shares a component. The router detects this correctly, but emitting a
   straight line for a 125 m leg whose endpoints are ~40 m from a real street
   is wrong. It should either repair to a nearby connected fragment or
   explicitly report "no foot path" instead of drawing a line.

2. **Five ride/transfer legs per itinerary have no geometry.** These come from
   the precomputed cache `data/route_geometry.json` for rail and long-distance
   bus track — untouched by this work. Same offline-cache approach could apply,
   or the rail graph could be built from the `rails/` extract.

3. **`roads.gpkg` is not in the repo.** `build_road_graph.py` hardcodes
   `C:\Users\cy1in\Downloads\roads\roads.gpkg` as its default. It should take a
   path argument or document the download step.

4. **No unit tests.** Only the two `verify_*.py` scripts. They are real
   assertions, but the repo has a `tests/` directory that this does not feed.

5. **`src/mobile/lib/data/models/itinerary.dart` and
   `src/mobile/test/itinerary_geometry_test.dart` had uncommitted changes before
   this work started** — they are in the zip but are not mine. Please review
   them independently.
