# Station placement + connectivity audit

Generated by `tool/audit_station_placement.py` against the live seed
(`data/seed_all_tunisia_routes.tagged.json`, 7 452 transit rows + 18 louage
hubs = 7 470 stops).

Every number below was produced by a committed script that can be re-run. The
verifier scripts exist because the first three versions of this audit were
WRONG in ways that looked like data defects, and each one is documented so the
mistake cannot be repeated silently.

## How to reproduce

```bash
# 1. water polygons (one-time; sources are downloaded, not fetched live)
python tool/build_water_polys.py --gshhg <gshhg-dir> --geofabrik <tunisia-shp-dir>
python tool/check_water_index.py          # 12 ground-truth points must all pass

# 2. the audit
python tool/audit_station_placement.py --json out/audit.json

# 3. the checks that keep the audit honest
python tool/verify_nearest_ground_truth.py --report out/audit.json
python tool/diagnose_rail_placement.py
python tool/crosscheck_water.py --report out/audit.json
python tool/inspect_louage_endpoints.py
```

### The 5 quarantined stations are still live on the map

This is the most serious finding, and it is not what the quarantine intended.

The seed quarantines a station by nulling its `lat`/`lon`, and the backend skips
rows with null coordinates. But **the same physical place exists as a second row
from another source, which kept the identical bad coordinate and was never
quarantined.** Nulling one row therefore removed nothing.

| quarantined row | coordinate it was quarantined for | duplicate row still served | verified live |
|---|---|---|---|
| `bir_mouzaina` | 37.16, 9.72 — inside Lake Ichkeul | `dl_bledi_curated_workbook_bir_mouzaina` | yes |
| `ajim` | 37.162, 9.735 — inside Lake Ichkeul; real Ajim is 393 km away on Djerba | `dl_bledi_curated_workbook_ajim` | yes |
| `douane_bir_mouzaina` | 37.155, 9.705 — inside Lake Ichkeul | `dl_bledi_curated_workbook_douane_bir_mouzaina` | yes |
| `ain_drahem` | 36.827, 10.35 — inside Tunis, 3 km from Carthage; the real town is in Jendouba | `dl_bledi_curated_workbook_ain_drahem` | yes |
| `srtgn_croisement_ghorfa_8e1674a84b` | 37.003307, 10.73375 — user-reported faulty point | `dl_srtgn_croisement_ghorfa_76199` | yes |

Checked against the running backend with
`curl /api/v1/stations/<id>` — all five return HTTP 200 with the bad
coordinates and are drawn on the map.

A second gap: `ajim` has a THIRD row, `dl_sntri_ajim_85358` at
33.7249, 10.7483, which is the correct Ajim on Djerba. So the correct position
was already in the seed while two wrong ones were being served.

### The 5 rail stops >5 km from track

Menzel Bouzaiane (14.0 km), Cheria (9.2 km), Menzel Gare (9.2 km),
Enfida (8.8 km), Benbachir (6.1 km).

These are NOT missing track: the lines serving them have 50–88% of their stop
pairs traced, and overall rail coverage is 483/539 pairs (90%). So these five
coordinates warrant a manual look — they are the only rail stops where the
station and the track disagree.

An earlier version of this audit reported 42 such stops. That was wrong: it
measured every station tagged `train`, including 220 intercity stops that are
not on any rail line in the network graph. `tool/diagnose_rail_placement.py`
joins each stop to its actual lines and finds 5.

| measure | count |

| stops served by more than one line | 904 |
| interconnected components | 3 (sizes 258, 3, 1) |
| lines sharing no stop with any other line | **1** |

The 258-line component is the national network: a rider can transfer between any
of those lines. One line, **42A (Menzel Belhouane – Mansoura)**, shares no stop
with any other line and is therefore unreachable — it cannot be boarded from the
rest of the network and cannot be transferred out of.

The 117 BizerteConnect lines are a different matter: their API publishes
endpoints and schedules but no stops, so they are not edges at all. They are
recorded as `unroutable_lines` in the seed metadata. Counting them as
"disconnected lines" would have been wrong.

Top interchange stops: Charle Nicole (31 lines), 20-mars (30), Jardin Thameur
(27), Dubosville (25), Centre De Coordination Ouardia (25).

Every louage terminal is within 888 m of a non-louage stop, so all of them
connect to the rest of the network. The furthest is Gare routière louage
(888 m), then Metlaoui (864 m), Gafsa (578 m).

An earlier run reported 33 of 47 as disconnected, at distances of 20–100 km.
That was a **broken haversine** in the audit itself (a double square root
inflating every distance ~10.5×; Tunis→Sousse read as 1 215 km instead of
115.6 km). With the correct formula, none are disconnected.

### Louage route endpoints: 29 of 59 routes point at no station

17 endpoint names in the louage route list resolve to no louage station id:

- **10 routes** use `yasmine_hammamet` as an endpoint. There is no Yasmine
  Hammamet station in the seed. It is a real resort area, so these routes are
  real but their terminus is missing from the station list.
- **8 endpoints are real Tunisian towns absent from the louage station list:**
  `beja`, `kelibia`, `zaghouan`, `bousalem`, `ras_jebel`, `korba`, `kebili`,
  `tozeur`, `kasserine` (each matches a transit stop name, so the place exists
  in the network — just not as a louage hub).
- **4 endpoints are not places at all:** `bus_line_115`, `bus_line_102`,
  `bus_line_115_hammamet` — a line identifier used where a station name belongs.
  `djerba`, `la_marsa`, `medina_hammamet`, `hammamet_nord` are place names that

### Limits of the water test

The water mask is built from GSHHG 2.3.7 full-resolution land polygons
(~100 m coastline) plus OSM water polygons from Geofabrik's Tunisia extract
(lakes, 530 reservoirs, 153 saltmarsh/chott polygons, 173 riverbanks).

- A **positive** (in water) is reliable: it is an exact ray-cast containment
  test, bbox-rejected first.
- A **negative** is weaker. GSHHG generalises at ~100 m and OSM's small
  reservoirs and sebkhas are incomplete, so "not in water" does not prove a
  point is dry — only that no mapped water body contains it at that resolution.

Natural Earth 10m was tried for the coastline and REJECTED: it is a
1:10,000,000 generalisation whose coastline classified La Marsa, Bizerte and
Carthage as open sea, while Nominatim confirms all three are residential land.

## Bugs found in the audit itself (all fixed)

| bug | symptom | fix |
|---|---|---|
| double square root in `haversine_m` | every distance ~10.5× too large; 33 louage "disconnected" | one `sqrt` |
| country bbox set to the network-coverage box | 34 real border towns reported "off-site" | Tunisia's true bounds (30.20–37.60 N, 7.45–11.65 E) |
| fixed-radius grid search | 4 541 false "no neighbour" | expand rings until found, then brute-force verify |
| land rings tested as water | La Marsa/Bizerte/Carthage as open sea | land and water kept separate |
| `self.w` used for both west bound and raster width | mask all-zero, every point "dry" | renamed `west`/`ncols` |
| polygons drawn unclipped | raster over-filled; 30 false "in water" | Sutherland-Hodgman clip + exact confirmation |
| per-point ray casting on a 1.16 M-vertex ring | audit timed out at 590 s | raster prefilter (now 28 s) |
| louage endpoint ids compared to names | 104 bogus "unresolved endpoint" | resolve against station ids |
