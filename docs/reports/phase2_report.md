## 2. Loop / duplicate / back-forth findings

- **Loops/duplicates: 1 line** — `bus_836_31b` with 1 duplicate station removed
  (`duplicates_removed_total: 1`). This is the only line in the seed whose station list
  contains a repeated id. `has_loop=false` for the other 378.
- **Back-forth (`is_single_direction=false`): 87 lines** — defined as ≥1 sharp reversal
  (cos angle < −0.8 between consecutive >200 m legs). Most are Tunis bus lines whose
  seed order contains a return leg appended at the end (e.g. `bus_842_33a` jumps back
  to Sidi Hsin mid-list), plus train lines `train_5/18/20/21/23/24_sncft`, `rail_19_a`,
  `metro_50_1`. Original order is preserved in every table (`original_stations`).
- **Corrected order offered for only 3 lines** (`train_18_sncft`, `train_24_sncft`,
  `bus_859_44d`): greedy nearest-neighbour re-order from the origin was stored as
  `corrected_order.direction_aller_corrected` **only** where it removes all reversals
  **and** halves path length. For the other 84 back-forth lines the sharp turns are
  real street geometry (out-and-back / loop routes) or stem from wrong-coord shared
  stations (below), so no corrected order was invented.
- **Teleport legs (>20 km between consecutive stops): 35 bus lines.** Root cause is
  shared station ids with a single wrong coordinate, e.g. `les_salines`:
  coord (36.078, 8.964) is used by `bus_708_17` (Rades) creating 142 km legs, and by
  `train_5_sncft` where `oued_tessa→tarf_echena` is a 77 km jump. Also end-of-list
  return termini, e.g. `bus_700_23` ends `cafe_medina→cite_el_intilaka` (25.1 km back
  to Tunis). These are recorded per-table in `teleport_legs` for Phase 3 station-id
  disambiguation; station coords were not altered.

## 3. Unknown-mode resolution (seed 76 unknown; transport_map_corrected has 77)

Method (reuse of seed `unknown_mode_resolution`, tolerance 150 m): single-line-mode
first, else nearest `station_reference.json` station with a known mode within 150 m
(spatial grid), else `station_name_mapping` name+proximity. Result:

- **Resolved: 47 / 76** — mostly bus (22), metro (17), train (4), rail (1), louage (2
  via single-line-mode: `bab_saadoun_7348`, `stil_7364`). Distances recorded per station
  in `data/phase2_summary.json:unknown_mode.resolved_detail`.
- **Left unknown: 29** (`left_unknown_ids` in summary) — no reference station within
  150 m and no serving line. They stay `unknown` (interim icon `bus.svg`); no mode invented.
- Note the 74/76 unknowns serve **no line at all** in the seed (`lines_served: []`),
  so line-based resolution could only help 2 of them.

   intermediate stops must come from SRT Bizerte, not geocoding.
6. **Commune-centroid >30 km check still impossible** (no centroid dataset) — unchanged from Phase 1.
7. **Stale seed metadata** (`coordinate_coverage: 1534`) untouched.
8. **Catalog rebuild with AR/FR names** not done (§7).
