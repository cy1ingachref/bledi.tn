# Provenance audit — data sources and licensing status

## Dataset under audit

- `data/seed_all_tunisia_routes.json` — source seed, 232 lines, 1,711 stations.
- `data/seed_all_tunisia_routes.tagged.json` — same records with `source` and
  `license_status` added to every station and line. Generated by
  `scripts/tag_provenance.py`. The original seed is not modified.

## High-level finding

Most of the routing data is derived from **Tunismapper**. The terms of that
source have not been verified for redistribution. For that reason this
repository does **not** yet claim a license for the dataset, and
`LICENSE.TODO` records that the license is undecided.

## What the source labels mean

- **tunismapper** — data derived from Tunismapper. The `source` string is
  literally `"tunismapper"` or a tunismapper URL. 227 of 232 lines and 1,315
  of 1,711 stations fall in this category.
- **transtu.com.tn PDF (Tebourba.pdf)** — built from a Transtu PDF for the
  Tebourba routes. 4 lines, tagged `official-public` as the most likely
  public-source case (should be confirmed against the actual publication).
- **official-public** — inferred official/public source. For lines, this is the
  4 Transtu PDF lines. For stations, this is inferred from the station's `mode`
  field when it is `train`, `metro`, `rfr`, `rail` or `tram` (SNCFT/ONCF rail,
  metro/TGM, RFR state buses) — a heuristic, not a confirmed citation.
- **unknown** — no source field on the record and no mode that maps to a known
  source. 130 stations have `mode: "unknown"` and are tagged `unknown`.

## What is NOT in this dataset

- **Louage routes.** `data/all_tunisia_bus_registry.json` holds louage operator
  and fare metadata and station location points, but no route geometry. Louage
  does not appear as routable lines in the seed.
- **Own field data.** No station or line is tagged `own-field-data`.
- **OSM-derived geometry flagged as open data.** No record currently carries an
  `osm-odbl` source.

## What would need to change before claiming a license

1. **Tunismapper-derived records (the bulk).** Either confirm in writing that
   Tunismapper permits redistribution or derivative datasets under a known
   license, or replace these records with data from a licensable or clearly
   open source.
2. **Transtu PDF lines.** Confirm whether the PDF is an official publication or
   a third-party compilation, and document the source accordingly.
3. **SNCFT/ONCF rail and metro/TGM data.** If these are to be relied on as
   official-public, gather and cite the specific official source used for each
   line or timetable. Currently these are tagged `official-public` as a
   heuristic based on the `mode` field.
4. **OSM.** If OSM geometries or stop locations are used in the future, note
   that OSM content is ODbL-licensed and requires appropriate attribution and,
   where applicable, share-alike handling.
5. **Own field data.** Stations or lines collected by you or your team could be
   tagged `own-field-data` and licensed under whatever terms you choose, which
   would help move the dataset toward a clear license story.

## Current code stance

The code does not assume the data is open-licensed:

- `LICENSE.TODO` states the license is undecided and points here.
- `README.md` links to this document and does not claim MIT or any other
  license for the dataset.
- The `/api/v1/itinerary` Tunismapper proxy is disabled by default precisely
  because the source's terms are unverified.

## Regenerating the tagged file

```
python scripts/tag_provenance.py
```

The script reads `data/seed_all_tunisia_routes.json`, adds `source` and
`license_status` to every station and line, and writes
`data/seed_all_tunisia_routes.tagged.json`. It refuses to overwrite an existing
tagged file. Station source is inferred from the station's `mode` field
(train/metro/rfr/rail/tram -> official-public, bus -> tunismapper, unknown ->
unknown); line source is preserved from the original seed.
